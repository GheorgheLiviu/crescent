# Crescent

A web page where people pick Windows apps and download one `Crescent.exe`. On a new PC the exe
installs the picked apps silently with winget (Windows Package Manager), then runs any scripts the
user ticked. A Mac version (Homebrew, `Crescent.app`) is built but not yet tried on a Mac
([docs/mac-plan.md](docs/mac-plan.md)).

![The installer window while installing](docs/screenshots/installer-installing.png)

## Run it on your own PC

You need the project folder (clone the GitHub repo, or copy the folder).

**Windows:** double-click **`setup.cmd`**. It starts a small local web server with Python and
opens the page at http://localhost:8765. Close the window to stop it. Without Python, it opens
`web\index.html` straight from the file, which works too.

**Mac or Linux:** `sh setup.sh` (needs Python 3).

**To change the code and run the tests** (Windows):

```bash
setup.cmd -Dev
```

It installs whatever is missing with winget (Go, Node.js LTS, Git), then the test packages and the
test browser, runs `tests/run.sh` and opens the page. On Mac or Linux, `sh setup.sh --dev` does the
same but expects Go 1.26+, Node 22 and Python 3 to be installed already. To build the installer
after changing `installer/`, see [Build the installer](#build-the-installer).

## How it works

1. **Pick.** On the page, tick apps (or a template such as Python, Java or Database), choose where
   they install, and tick any scripts to run at the end.
2. **Download.** The page takes the prebuilt Go program (`web/installer-base.js`), appends the picked
   list to its end and saves the result as `Crescent.exe`. Nothing is sent to a server; it all
   happens in the browser.
3. **Run on the new PC.** The exe asks for admin once, reads the list from its own end, shows a setup
   window, installs each app silently with `winget` (skipping ones already installed), runs the
   ticked scripts and ends with a summary.

Details of the payload, the exe and the window: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## For the person using it

- Open the page, pick apps, click **Download installer**, copy `Crescent.exe` to the new PC
  and double-click it.
- The exe is unsigned, so Windows SmartScreen warns the first time: click **More info**, then
  **Run anyway**.
- Needs Windows 10 or 11 with winget (App Installer) and internet. If winget is missing, the
  installer offers to open the Microsoft Store to get it. Without WebView2 it falls back to simple
  message boxes.
- No clicks are needed while it runs, except for Samsung Magician, whose own setup needs them.

## Status

- Tested on real Windows 11: apps from winget and the Microsoft Store, a chosen install folder,
  PostgreSQL with its password file, Microsoft 365, Samsung Magician, scripts and weekly updates.
- Not tried yet: Windows 10, high-DPI screens, and the Mac version on a real Mac.
- There is no public hosting yet; run the page locally (below).

## Folder map

```
web/          the web page: exactly the files that get published
installer/    the Go program that becomes Crescent.exe, and its built base exe
scripts/      the project's script library (source for web/scripts.js)
tools/        Python helpers that generate files and check the catalog
tests/        all automated tests, one command
docs/         architecture, Mac plan, screenshots
```

| Path | What it is |
|---|---|
| `web/index.html` | The web page: catalog, templates, scripts list, Package panel. It builds the installer in the browser. Has the doctype, charset and viewport tags, so it can be served as it is. English and Romanian (ENG | RO switch, texts in `const I18N`). |
| `web/apps.js` | The app catalog: groups, apps, Romanian names, templates, starter apps, maker downloads, apps that can't change folder. Plain JSON after the first line; edit it by hand (see "Add an app"). `tools/apps_data.py` reads and writes it for the tools. |
| `web/icons.js` | App icons as data URIs (`window.APP_ICONS`, 112 entries: every catalog app has one). Generated by `tools/build_icons.py`. |
| `web/scripts.js` | The script library for the page (`window.SCRIPT_LIBRARY`). Generated by `tools/build_scripts.py` from `scripts/`. Don't edit it by hand. |
| `web/installer-base.js` | `installer/Crescent-base.exe` as base64 (`window.CRESCENT_EXE_B64`). Generated after each installer build. |
| `web/installer-mac.js` | The Mac program (Apple silicon and Intel in one file) as base64 (`window.CRESCENT_MAC_B64`), loaded only on the Mac page. Built by `python tools/build_mac.py`. |
| `installer/` | Go source of the exe, its window (`ui.html`), Windows resources (`winres/`, `rsrc_windows_amd64.syso`), Go tests and rebuild notes. |
| `installer/Crescent-base.exe` | The built Go program with no app list (4,244,480 bytes). The page appends the list. |
| `scripts/` | The project's script library: `scripts.json`, `windows/*.ps1` and a how-to. |
| `tools/` | Python helpers: `apps_data.py`, `build_icons.py`, `build_scripts.py`, `check_catalog.py`, `location_support.py`; and `screenshots.mjs`, which retakes `docs/screenshots/`. |
| `tests/` | `run.sh`, the browser tests, `helpers.mjs`, `package.json` and a README. |
| `docs/` | `ARCHITECTURE.md`, `mac-plan.md`, and `screenshots/` (8 PNGs of the page and the installer window, retaken with `node tools/screenshots.mjs`). |
| `setup.cmd`, `setup.ps1`, `setup.sh` | Run the page locally; with `-Dev` / `--dev` also set up the tests (see "Run it on your own PC"). |
| `README.md`, `LICENSE` | This file and the MIT licence. |

## Run the page locally

Open `web/index.html` straight from disk in Chrome or Edge (double-click it, or use a `file://` URL).
That is how the tests load it, in Playwright's Chromium. It loads `apps.js`, `icons.js`, `scripts.js` and
`installer-base.js` from the same `web/` folder. Fonts come from Google Fonts, so without internet the page
uses fallback fonts.

Outside the Claude viewer, "Download installer" saves `Crescent.exe` directly. Inside the
Claude viewer it saves `Crescent.zip` with the exe inside.

The page can be served as it is from any static host (it has the doctype, charset and viewport
tags). Serve it as UTF-8. Firefox and Safari were not tried.

## Build the installer

Needs Go 1.26 or newer (on Windows: `winget install GoLang.Go`). The commands come from [installer/README.md](installer/README.md).

**Linux or Git Bash:**

```sh
cd installer
go install github.com/tc-hib/go-winres@v0.3.3          # once
go-winres make --in winres/winres.json --arch amd64     # rewrites rsrc_windows_amd64.syso (icon, admin manifest, version)
GOOS=windows GOARCH=amd64 CGO_ENABLED=0 go build -trimpath -ldflags "-s -w -H windowsgui" -o Crescent-base.exe .
{ printf 'window.CRESCENT_EXE_B64="'; base64 -w0 Crescent-base.exe; printf '";\n'; } > ../web/installer-base.js
```

On macOS, `base64 -w0` doesn't exist. Use `base64 < Crescent-base.exe | tr -d '\n'` in its
place (not tried).

**Windows PowerShell**, from the project folder:

```powershell
cd installer
go install github.com/tc-hib/go-winres@v0.3.3
go-winres make --in winres/winres.json --arch amd64
$env:GOOS = "windows"; $env:GOARCH = "amd64"; $env:CGO_ENABLED = "0"
go build -trimpath -ldflags "-s -w -H windowsgui" -o Crescent-base.exe .
$b64 = [Convert]::ToBase64String([IO.File]::ReadAllBytes("$PWD\Crescent-base.exe"))
[IO.File]::WriteAllText("$PWD\..\web\installer-base.js", "window.CRESCENT_EXE_B64=`"$b64`";`n")
```

After a build, always regenerate `web/installer-base.js`. The page test "installer-base.js holds the
same program as Crescent-base.exe" fails if you forget.

**The Mac program** (after any change in `installer/`, on any computer with Go and Python):

```sh
python tools/build_mac.py   # builds for Apple silicon and Intel, joins them, writes web/installer-mac.js
```

## Run the tests

```sh
sh tests/run.sh        # or: cd tests && npm test
```

It runs the Go tests, `GOOS=windows go vet .`, a Windows build to `/dev/null`, then
`node --test tests/*.test.mjs`. It needs Go, Node 22 and Playwright 1.56.1 with Chromium.

- **First time on a new machine:** `cd tests && npm install && npx playwright install chromium`.
- **Windows:** run `sh tests/run.sh` from Git Bash. The Go tests are all
  marked `//go:build !windows`, because they run small `sh` scripts as a stand-in winget, so
  `go test` finds none on Windows and `e2e.test.mjs` skips itself there. On Windows, run.sh vets and
  builds the Go program and runs the page and installer-window tests. Run the Go tests on Linux or
  in WSL with a Linux distribution installed.


## Add an app to the catalog

1. Find the app's winget ID (for example with `winget search`, or on https://winget.run). Store
   apps use their 12-character Store ID, such as `9NKSQGP7F2NH`.
2. Open **`web/apps.js`** (plain JSON after the first line) and add
   `{"name": "Display name", "id": "Winget.ID"},` to the right group's `"apps"` list. For a Romanian
   name that differs, add `"ro": "..."`. A new group needs `"name"` and `"ro"`. Templates, the apps
   ticked at the start (`starter`) and maker downloads are in the same file. No comma after the
   last item of a list.
3. If the app isn't in winget, it can only be added as a maker download in `"downloads"` (`url`,
   `detect`, `from`). The installer only allows hosts listed in `installer/direct.go`
   (today only `download.semiconductor.samsung.com`), so a new host needs an installer rebuild.
4. Install folder support: run `python3 tools/location_support.py --write`. It rewrites
   `"fixedLocation"` in `web/apps.js`.
5. Check the IDs: `python3 tools/check_catalog.py`. Both tools keep a copy of Microsoft's winget
   catalog in `~/.cache/winget-pkgs` (change it with `--cache`) and need git and network access to
   GitHub.
6. Icon: add the ID to `ICONS` in `tools/build_icons.py` and run `python3 tools/build_icons.py`
   (needs network and Pillow). It writes `web/icons.js`. Apps without an icon get a coloured letter
   tile.
7. Mac: add the Homebrew package to `"mac"` in `web/apps.js` as `kind:name`, for example
   `cask:firefox` or `formula:git`. Leave Windows-only apps out; they don't show on the Mac page.
8. Open source: add its source code link to `"repos"` in `web/apps.js` (an `https://` link). The
   page shows a small `<>` link on its row.
9. Run the tests.

## Add a script to the library

1. Put the file in `scripts/windows/` (`.ps1`, `.cmd` or `.bat`, UTF-8, safe to run twice), and a
   Mac version, if any, in `scripts/mac/` (`.sh`).
2. Add an entry to `scripts/scripts.json` (`id`, `name`, `description`, `windows`, `mac`).
3. Run `python3 tools/build_scripts.py`. It checks every entry and writes `web/scripts.js`.
4. Run the tests.

Rules and an example entry: [scripts/README.md](scripts/README.md).
